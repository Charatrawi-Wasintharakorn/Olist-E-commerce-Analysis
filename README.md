# Olist E-commerce Sales Analysis

โปรเจกต์วิเคราะห์ข้อมูลธุรกรรมของ Olist Brazilian E-Commerce เพื่อเปลี่ยนข้อมูลดิบหลายตารางให้เป็นข้อมูลยอดขายที่ตรวจสอบได้ และตอบคำถามทางธุรกิจว่า **ยอดขายเติบโตอย่างไร และหมวดสินค้าใดเป็นตัวขับเคลื่อนรายได้**


## ผลการวิเคราะห์

| ตัวชี้วัด | ผลลัพธ์ |
|---|---:|
| ข้อมูลดิบที่ใช้ | 8 ตาราง, 1,451,698 แถว |
| ออเดอร์ที่ส่งสำเร็จและผ่านการตรวจสอบ | 95,097 ออเดอร์ |
| ยอดขายรวม | ประมาณ R$13.05 ล้าน |
| ยอดขายช่วง ม.ค.–ก.ค. 2018 เทียบกับช่วงเดียวกันในปี 2017 | **เติบโต 156.1% YoY** |
| ค่าเฉลี่ย MoM ของ 6 เดือนล่าสุด เทียบกับ 6 เดือนก่อนหน้า | **-1.9% เทียบกับ +14.2%** |
| รายได้จาก 5 หมวดสินค้าสูงสุด | 39.8% ของยอดขาย |
| จำนวนหมวดที่รวมกันสร้างยอดขายอย่างน้อย 80% | 18 จาก 74 หมวด (24%) |

**ข้อค้นพบหลัก:** ยอดขายช่วง ม.ค.–ก.ค. 2018 สูงกว่าช่วงเดียวกันของปีก่อนอย่างมาก แต่ค่าเฉลี่ยการเปลี่ยนแปลงรายเดือนใน 6 เดือนล่าสุดต่ำกว่าช่วงก่อนหน้า จึงเป็นสัญญาณว่าการเติบโตชะลอลง ไม่ใช่หลักฐานว่ายอดขายทั้งช่วงลดลง ขณะเดียวกัน รายได้ไม่ได้กระจุกอยู่เฉพาะไม่กี่หมวด โดยต้องใช้ 18 จาก 74 หมวดจึงครอบคลุม 80% ของยอดขาย

หมวดที่ทำรายได้สูงสุด 5 อันดับแรก ได้แก่ `health_beauty`, `watches_gifts`, `bed_bath_table`, `sports_leisure` และ `computers_accessories` รวมกันคิดเป็น 39.8% ของยอดขาย

## วิธีดำเนินงาน

1. โหลดข้อมูล Olist จำนวน 8 ตาราง โดยไม่ใช้ตารางรีวิว
2. ตรวจสอบค่าว่าง ค่าซ้ำ คีย์หลัก ความสัมพันธ์ระหว่างตาราง และลำดับเวลาของสถานะออเดอร์
3. สร้างตารางระดับออเดอร์ โดยนับเฉพาะออเดอร์ `delivered` ที่มีวันที่ลูกค้าได้รับสินค้า
4. ตัดออเดอร์ที่ลำดับวันที่ผิดปกติ 1,373 รายการ จาก 96,470 ออเดอร์ที่ส่งสำเร็จและมีวันที่ได้รับสินค้า ก่อนนำไปวิเคราะห์
5. คำนวณรายได้รายเดือน, MoM, YoY และสัดส่วนรายได้สะสมตามหมวดสินค้า (Pareto)
6. ตรวจสอบว่ายอดขายรวมจากหมวดสินค้าตรงกับยอดขายรวมในตารางออเดอร์
7. ส่งออกตารางที่เตรียมแล้ว เพื่อนำไปใช้ต่อใน SQL และ Power BI

**นิยามที่ใช้**

- รายได้คำนวณจากผลรวม `price` ของรายการสินค้า ไม่รวมค่าขนส่ง (`freight_value`)
- ใช้เฉพาะออเดอร์ที่จัดส่งสำเร็จและมีวันที่ลูกค้าได้รับสินค้า
- นับลูกค้าด้วย `customer_unique_id` เมื่อต้องการระบุลูกค้าซ้ำข้ามออเดอร์
- การวิเคราะห์แนวโน้มรายเดือนใช้เดือนที่ข้อมูลครบ โดยช่วงที่ใช้คำนวณคือ ม.ค. 2017–ก.ค. 2018 (19 เดือน)

## เครื่องมือ

- **Python:** pandas, NumPy, Matplotlib
- **SQL:** SQL Server
- **Dashboard:** Power BI
- **Data source:** [Olist Brazilian E-Commerce Dataset](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)

## วิธีใช้งาน

1. เปิด `data/olist.ipynb` ใน Jupyter Notebook หรือ Google Colab
2. รันเซลล์ตามลำดับเพื่อโหลด ตรวจสอบ และวิเคราะห์ข้อมูล โดยโน้ตบุ๊กใช้ `kagglehub` เพื่อดาวน์โหลดชุดข้อมูลจาก Kaggle
3. ใช้ไฟล์ SQL ใน `sql/` กับฐานข้อมูล SQL Server ที่เตรียมตาราง Olist ตามที่ query อ้างอิง
4. เปิด `dashboard/Data.pbit` ด้วย Power BI Desktop และกำหนดแหล่งข้อมูล/เส้นทางไฟล์ตามสภาพแวดล้อมของคุณ

## ข้อจำกัดในการตีความ

- YoY เปรียบเทียบเฉพาะเดือนมกราคมถึงกรกฎาคมของปี 2018 กับเดือนเดียวกันของปี 2017 ไม่ใช่การเปรียบเทียบยอดรวมทั้งปี
- เดือนเริ่มต้นที่มีออเดอร์น้อยและเดือนสุดท้ายที่ข้อมูลไม่ครบถูกตัดออกจากการวิเคราะห์แนวโน้ม
- ชุดข้อมูลครอบคลุมประมาณสองปี จึงยังสรุปฤดูกาลระยะยาวไม่ได้
- ออเดอร์ที่มีวันที่ผิดลำดับถูกตัดออกเพื่อให้การวิเคราะห์ยึดข้อมูลจัดส่งที่สมเหตุสมผล ผลลัพธ์จึงขึ้นกับกติกาการคัดกรองนี้
